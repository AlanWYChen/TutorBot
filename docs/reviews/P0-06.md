# P0-06 — Model gateway and provider capabilities

Status: implemented, awaiting user review. P0-01 through P0-04 approved.

## Delivered

- Provider-neutral async `ModelGateway`: text, structured output, tool proposals,
  images and embeddings, with Pydantic-normalized results and usage/route metadata.
- One shared registry for all six logical aliases, provider IDs, key selection,
  capabilities, context/output bounds, service permissions and explicit fallbacks.
  API startup and proxy rendering fail closed on unknown or cross-modal models.
- Tutor substitution from OpenAI to DeepSeek through `TUTOR_MODEL` only. Vision
  stays on its verified route, and embeddings/profile database remain unchanged.
- Separate native JSON Schema and explicitly selected validated-JSON mode;
  malformed output, unknown tools/arguments, refusal and truncation are rejected.
- Runtime cannot use teaching-distillation. The gateway proposes tools and never
  executes them or stores provider-hosted conversation state.
- Bounded inputs and sanitized provider errors. Fallback is explicit in trace
  metadata; unsupported/default calls refuse before transport. There is no
  application retry or error-driven fallback.
- Embedding index compatibility checks and complete model/dimension/content hash/
  chunker/index-release metadata, with no cross-model embedding fallback.
- Repeatable isolated pinned-proxy integration tests and CI/Makefile wiring.

## Acceptance evidence

- API/renderer lint and strict application types pass.
- 64 API unit/SDK/domain/gateway tests pass, including 37 gateway cases.
- Two real pinned LiteLLM proxy tests pass: OpenAI and DeepSeek. Both exercise
  text, structured JSON, function proposals, image routing and embeddings.
  The synthetic provider checks dispatched model IDs and credential families.
- DeepSeek native-schema/image requests refuse by default. Explicit JSON-object
  mode validates locally; an explicitly permitted capability fallback records
  its selected alias and reason. Vision transport is only sent to OpenAI.
- Invalid JSON, invented tools, forged extra student IDs, wrong argument types,
  non-finite/wrong-dimension vectors, changed index model/dimensions, unsafe
  proxy URLs, timeout, auth/rate failures and truncated/refused output fail closed.
- Six existing real Firebase/PostgreSQL integration checks pass, retaining
  account ownership, admin separation, global write isolation, audit immutability
  and migration rollback constraints. No database migration or profile code changed.
- Web lint/types and seven tests pass. Eight primary services are healthy;
  runtime, maintainer and web readiness smoke checks pass.

Total: 79 passing tests across unit, service, proxy and web suites. Integration
cases skipped in the isolated unit run are executed by the service/proxy commands.
Test-only proxies have no provider internet access or host ports; they are stopped
when the command exits. No paid inference or real student content was used.

## Review scope and remaining work

This step supplies the gateway component and configuration, without introducing
public inference or tutoring handlers before their own tickets. Streaming is
recorded in the registry, while gateway responses are completed and validated.

Synthetic dispatch tests establish transport, capabilities and schema handling.
Actual account/model availability, pedagogical quality, math/tool regressions,
comparative cost and live-provider quality require the later staging/provider-
substitution gate. Additional models/providers remain disabled until registered
with capability evidence and tested. Arbitrary dictionaries require validated-JSON
mode or a bounded typed schema rather than native strict transport.
