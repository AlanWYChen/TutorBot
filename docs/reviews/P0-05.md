# P0-05 — Upload safeguards and private object storage

Status: implemented, verified and approved by the user. P0-01–P0-04, P0-06 and P0-07 approved.

## Delivered

- Separate authenticated student and maintainer multipart PDF uploads, private
  original downloads and durable verification status. No client-controlled student
  scope, storage path, source promotion or worker action.
- Shared 25 MiB/200-page limits (fixing the earlier 20/25 MiB adapter mismatch),
  declared/streamed body enforcement, bounded metadata/parts/concurrency and receive
  deadlines. Authentication runs before multipart parsing; temporary files close.
- Independent extension/MIME/signature/EOF/actual-size/SHA-256/page-count checks.
  Resource-bounded native inspection refuses malformed, encrypted, repaired,
  active-content, attachment and over-page-limit PDFs with sanitized errors.
- Idempotent owner-derived resources, transactional metadata/manifests/jobs,
  conflict rejection and no resurrection after deletion. Actual private originals
  retain their bytes and generation; downloads require trusted ownership.
- Student assessments remain unverified. Maintainer metadata and licensing are
  retained with trusted authorship; uploaded sources remain draft in teaching-private.
  No extraction, profile updates, global learning or publication is triggered.
- Fixed attachment filenames, no-store/nosniff/sandbox headers, route-template audit
  events and updated OpenAPI/typed catalog, Makefile and CI acceptance gate.

## Review scope and limitations

This is the backend safeguard step. Student upload UI, page rendering/viewer and
question coordinates arrive in P1-01. Storage verification success does not imply
extraction, grading or mathematical verification. Native limits/refusals are a
validation policy, not a complete malware guarantee or deployed parser sandbox.

Fake-GCS does not enforce production IAM. Real-cloud privacy, signing, retention,
containment and orphan reconciliation remain staging gates. If DB commit fails
following a private write, an identical retry can recover it; uncommitted objects
have no API access path. Raw source fixtures are cleaned up after integration tests.
