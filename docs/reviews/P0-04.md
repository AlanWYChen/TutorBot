# P0-04 — Initial domain schema and typed contracts

Status: implemented, verified, and approved by the user. P0-01 through P0-03 approved.

## Delivered

- Initial section 4 domain schema: 47 total tables, including 40 new tables,
  existing identity/audit metadata and expanded knowledge/skill records.
- Separate private student documents/evidence and maintainer source materials;
  composite owner relationships, forced row policies and verified-principal scope.
- Distinct raw evidence, recomputable concept/trait states, versioned profile
  summaries and student-only memory. No-evidence states remain explicitly unknown.
- Source-document constraints for chunks/demonstrations; question regions must
  belong to their assessment document; sessions require published release pins.
- Maintainer-only evaluation partitions, including holdout cases.
- Pydantic contracts and exported JSON Schemas for all 18 section 5 operations,
  including bounded upload metadata, evidence references and resolved context.

Review [schema inventory](../schemas/domain-v1.md),
[API schemas](../contracts/v1.json), and [design decision](../adr/0004-domain-schema.md).
This is a backend foundation step; it adds no new student interface.

## Acceptance evidence

- API lint and strict application type checks pass.
- 27 API unit/SDK/contract tests pass; 6 real-service integration tests pass.
- Web lint/types and 7 web tests pass; all 8 local services are healthy.
- Runtime, maintainer and web readiness smoke checks pass.
- Disposable DB migrations tested P0-03 → head → P0-03 → head → base → head.
  Legacy rows survive and unlinked legacy chunks are hidden after upgrade.
- All private links include composite owner keys. Missing scope sees no rows;
  cross-student reads/writes and source links fail. Transaction commit/rollback
  clears scope. Actual runtime/admin logins are used for isolation checks.
- Runtime cannot access or update any of the 19 global base tables, modify raw
  evidence/history, or read evaluation holdout views. Admin cannot read private
  student history. Existing authentication/audit/service tests still pass.
- Invalid upload size/page/hash/media type/path, client student ID, reversed
  cohort, unsupported trait level and proficiency without evidence are rejected.

Only synthetic fixtures were used, and domain fixtures live in a disposable DB.
No official curriculum, rubric, learning trait or real student data was seeded.

## Scope and remaining work

The new operation contracts are not mounted placeholder endpoints. Upload byte
inspection, processing jobs, extraction/corrections UI, profile algorithms,
retrieval and publishing behavior belong to subsequent tickets. Optional vectors
have no fixed dimension/index until the model capability configuration is verified.

RLS protects against missing filters, while trusted identity resolution and
service credential isolation remain necessary. Production IAM and the phase 0
security gate are still pending. Release immutability and evaluation approval
workflow are delivered by the release pipeline tickets.

There are two non-blocking test notices: the pinned FastAPI test client deprecation,
and SQLAlchemy's generic inspector not recognizing the vector extension type.
The database vector column is verified by migrations; application vectors are
not yet queried.
