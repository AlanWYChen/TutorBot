# P0-07 — Private object storage and durable job adapters

Status: implemented, awaiting user review. P0-01–P0-04 and P0-06 approved.

## Delivered

- Provider-neutral `ObjectStorage` and `JobDispatcher` protocols. The same GCS SDK
  targets fake-GCS locally and ADC-authenticated private GCS buckets in cloud.
- Separate student-private, curriculum-published and teaching-private bucket
  contracts. Owner/assessment/resource UUID keys never contain filenames or text.
- Generation-conditional uploads/reads/deletes, bounded downloads, SHA-256 checks,
  size/media validation and retention metadata in immutable database manifests.
  Repeated uploads preserve the original generation; conflicting bytes refuse.
- Migration `0005_private_io`: scoped manifests and durable job outboxes in separate
  student/maintainer schemas. Student records have forced RLS and composite owner
  keys. Tombstones hide deleted objects, block new jobs and cancel active attempts;
  repeated physical deletion remains recoverable from the retained manifest.
- `enqueue/status/cancel` resolved from verified principals. Idempotency keys have
  per-owner uniqueness and cannot be reused for another object.
- Separate Celery workers/relays and narrow SQL worker credentials, JSON-only
  reference messages, durable relay recovery, atomic claims, lease-token fencing,
  bounded retries and cancellation. No Celery calls enter domain logic.
- A real replay-safe `verify_object` handler. No parsing/upload/tutoring routes are
  added ahead of their own tickets.
- Fixed Cloud Tasks HTTPS/OIDC and Cloud Run Jobs request contracts, shared worker
  entry point, signed-access TTL bounds and an explicit real-cloud staging plan.
- Worker/relay health checks, persistent Compose services, pinned dependencies,
  repeatable Makefile acceptance gate and CI integration.

- API/renderer lint and strict application types pass; 68 unit/SDK/domain/model
  tests pass, including four new storage and cloud-contract tests.
- Four real PostgreSQL/fake-GCS/Celery cases pass: immutable object upload/read/

## Review scope and remaining work

This step provides adapter infrastructure, without public upload/job handlers.
Only immutable source verification is currently registered as a worker action.
Future derived-write handlers must fence their commits and make every external
side effect idempotent; Celery delivery is at least once.

The emulator cannot establish IAM or signature security. Local signed access
explicitly refuses. Cloud contracts are tested request shapes, not deployed cloud
workers; ADC transport, verified OIDC receiver, IAM, signing-capable credentials,
lifecycle policy, orphan reconciliation and real delivery failures are required
staging checks. Recorded retention dates do not enforce a cloud retention lock or
schedule deletion. The staging plan specifies those checks and cleanup.
